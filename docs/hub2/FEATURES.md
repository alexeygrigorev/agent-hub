# Hub 2.0 feature inventory

Status: revised source/usage inventory, 4 November 2026. KEEP preserves a required externally visible behavior. MERGE preserves behavior under one owner/model. DROP excludes a separately identified implementation surface; it must not remove a retained contract hidden in the same module.

Version discrepancy: the local bots-management AGENTS.md and hub-sessions skill inspected for this revision do not contain the newer “Project selection”/hub repos instructions reported by Alexey. His explicit correction nevertheless requires the canonical registry, `hub repos list --status active`, `hub repos show <candidate>` and operator `hub repos edit`. Existing source independently establishes these contracts in src/mcp-tools.ts:8–10. Preserve them; do not infer absence of use from a stale skill checkout. Re-read the then-current instructions before implementation.

No complete usage-analytics export was supplied. No production telemetry was queried in this architecture task. Before removing a DROP surface, inspect approved consumer telemetry and confirm no active consumer; lack of a keyword in one skill is insufficient. Source interfaces prove implemented capability, while skills/direct instructions establish required behavior; neither proves the disabled production service currently delivers it.
